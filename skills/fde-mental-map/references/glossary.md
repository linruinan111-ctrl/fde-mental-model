# FDE 分层术语词典

这是查阅索引，不是每次问题都要完整输出。

## 网络与基础设施

| 名词 | 是什么 | 关键判断 |
|---|---|---|
| IP | 设备/接口在网络上的逻辑地址 | 一个机器可以拥有多个 IP |
| 公网 IP | 互联网上可路由的地址 | 有公网 IP 不代表端口对外可达 |
| 私网 IP | 在内网地址空间使用的地址 | 外部通常无法直接路由访问 |
| Port 端口 | 区分一个地址上的传输层服务 | 监听端口不代表已映射/放行 |
| DNS | 将域名解析为地址等记录的系统 | 解析成功不代表应用成功 |
| HTTP | Web 常用的请求/响应协议 | HTTP 与 TCP 是不同层 |
| HTTPS/TLS | 为 HTTP 连接提供加密与身份验证 | 证书、域名和握手可能独立失败 |
| NAT | 网络地址或端口转换机制 | 入口 IP 可能不是应用主机 IP |
| Firewall | 控制网络流量通行的规则 | 云安全组和系统防火墙可以同时生效 |
| Nginx | Web 服务器与反向代理软件 | 代理不是 VM 或 Docker 本身 |
| Reverse proxy | 代表上游服务接入并分发请求 | 不等于正向代理 |
| Gateway | 请求入口或控制/转发角色 | 不一定是独立硬件 |
| VPN | 建立受控网络连接的技术 | 连 VPN 不代表拥有全部系统权限 |
| Load Balancer | 将请求分配到多个服务实例 | 可能置于 Nginx 前面 |

## 服务器与容器

| 名词 | 是什么 | 关键判断 |
|---|---|---|
| Server | 提供计算/网络服务的计算机或实例 | 可为物理或虚拟 |
| VM | 虚拟机，模拟独立计算机系统 | 通常具备自己的客户 OS |
| Hypervisor | 分配和隔离 VM 计算资源的层 | 和容器运行时不同 |
| Linux | 操作系统内核与发行版生态 | Linux 不等于 Shell |
| Shell | 与系统交互的命令解释器 | Bash/zsh 是具体 Shell |
| Docker | 构建、管理、运行容器的平台 | 不是所有项目都必须用它 |
| Image | 容器镜像，应用与依赖的模板 | 镜像不等于运行中服务 |
| Container | 容器，隔离的进程实例 | Running 不意味着 Healthy |
| Volume | 用于跨容器生命周期保存数据 | 未持久化数据可能随容器重建丢失 |
| Compose | 声明和管理一组容器的工具 | 不等于 K8s |
| Kubernetes | 容器编排、调度、扩缩容系统 | 小规模系统不一定需要 |

## 应用与数据

| 名词 | 是什么 |
|---|---|
| Frontend | 用户交互界面 |
| Backend | 处理业务规则、鉴权、数据访问的程序 |
| API | 不同程序之间的调用契约 |
| curl | 发送 HTTP 等请求的命令行工具 |
| Database | 持久存储和查询业务数据的系统 |
| SQL | 关系型数据库常用的查询语言 |
| Redis | 常见缓存、临时状态、协调等用途的数据服务 |
| OSS / Object Storage | 存储 PDF、图片、附件等对象文件 |
| Worker | 处理异步任务的执行单元 |
| Queue | 缓冲与分发待执行任务 |
| Log | 程序运行及异常事件记录 |
| Metrics / Traces | 系统指标与请求追踪信息 |

## AI 应用与自动化

| 名词 | 是什么 | 关键判断 |
|---|---|---|
| LLM | 大语言模型 | 模型能力与局限 |
| Model API | 程序调用模型推理的接口 | 超时、限流、鉴权、成本 |
| Context | 模型当前可见输入上下文 | 不等于永久记忆 |
| RAG | 先检索相关信息，再增强模型生成 | 不是所有任务都需要 RAG |
| Embedding | 将内容映射为向量表示的技术 | 语义检索用途之一 |
| Vector DB | 支持向量存储/检索的数据库 | 并非知识库必备独立服务 |
| Agent | 结合模型与工具完成多步行动的系统 | 任务权限、状态与可恢复性 |
| Tool Calling | 通过工具接口访问外部操作 | 调用参数和结果需要校验 |
| Playwright | 浏览器自动化工具 | 录制一次不保证长期稳定 |
| MaxKB | AI 知识库与问答应用平台 | 是应用，不是底层大模型 |

## 开发与发布

| 名词 | 是什么 |
|---|---|
| Git | 版本控制系统 |
| GitHub | 代码托管和协作/自动化平台 |
| PR | 代码合并请求 |
| CI | 持续集成：自动检查、测试和构建 |
| CD | 持续交付或部署 |
| GitHub Actions | 执行自动化工作流的平台能力 |
| Deployment | 将指定版本部署至指定环境 |
| Rollback | 恢复到此前已知可用状态 |
| Health Check | 判断服务是否存活/就绪的检测 |
| Secret | 应妥善管理的密钥或敏感配置 |

## 必须会区分

- **Server / VM / Container**：提供服务的计算环境 / 虚拟化计算机 / 隔离进程运行实例。
- **Domain / IP / Port**：可读名称 / 网络地址 / 服务端点的编号。
- **Image / Container / Volume**：模板 / 运行实例 / 数据持久化。
- **PR merged / deploy succeeded**：代码被合并 / 指定版本实际部署且得到验证。
- **RAG / Agent**：检索增强生成的方法 / 用工具和状态推进多步任务的系统。
