# FDE 故障排查剧本

## 总原则

开始排障前先记录：具体现象、发生时间、影响范围、客户所在网络、目标 URL、HTTP 状态码、最近变更、已确认事实。

采用 **观察 -> 假设 -> 最小安全验证 -> 解释证据 -> 下一步**。只读优先，不擅自改生产环境。

## A. Docker Running，但公网网站访问失败

~~~text
浏览器访问
  |
  +-- DNS 解析异常？ --> 核对解析记录
  |
  v
网络连接成功？
  | 否                     | 是
  v                        v
公网入口/路由/NAT/       HTTPS 握手成功？
安全组/防火墙/端口            |
                           v
                         HTTP 状态？
                          ├── 502/504 代理上游/超时
                          ├── 401/403 认证或授权
                          ├── 404     路由或路径
                          ├── 500     应用/依赖
                          └── 200但异常 前端或业务 API
~~~

如果能连接到宿主机，还需分辨：

~~~text
宿主机端口监听 --> Docker 端口映射 --> 容器内部监听
                                  --> 应用健康状态 --> 下游依赖
~~~

只读示例，操作之前一定核对主机、容器名、授权范围：

~~~bash
# 在 Docker 宿主机执行，检查容器状态及端口发布
docker ps

# 在 Docker 宿主机执行，检查端口绑定、网络设置、健康状态
docker inspect CONTAINER_NAME

# 在 Docker 宿主机执行，查看最近 100 行日志（分享前脱敏）
docker logs --tail 100 CONTAINER_NAME

# 在目标主机本机执行，替换成真实端口与真实健康路径
curl -I http://127.0.0.1:8080/health
~~~

这些命令是学习示例，不代表你的项目一定有 /health，也不应照抄固定端口。

解读：容器 Up 只能证明容器进程存在；本机 curl 通不能证明公网通；Nginx 502 只说明代理连接上游出问题或收到异常响应，需要进一步证实根因。

## B. GitHub PR merged，但网站没有更新

检查链：

1. PR 合并到了哪个分支？是否为部署所需分支？
2. Workflow 的触发条件、分支过滤、路径过滤是否满足？
3. 是否真的存在 Actions Run？结果如何？
4. 构建制品（镜像 digest/commit SHA）是否发布？
5. CD 的目标环境、审批与权限是否正确？
6. 线上运行版本是否指向该构建产物？
7. 入口流量、CDN/浏览器缓存是否让旧页面仍被访问？

**代码合并、流水线成功、生产服务可用，是三个不同的事实。**

## C. Windows Agent / Playwright 时好时坏

按顺序区分：

~~~text
用户提交任务 -> 控制 API -> 任务存储/队列
                              |
                       Agent 心跳/领取
                              |
                           Worker
                              |
                   浏览器 / Playwright
                              |
                        内部业务系统
                              |
                       结果与日志回传
~~~

- 任务是否被正确创建与排队？
- Agent 是否在线、认证是否有效、是否真正领取了任务？
- Worker 是否成功启动，是否存在并发限制？
- Playwright 的元素定位、超时、会话是否出现问题？
- 业务站点响应是否异常？任务重试是否幂等？
- 结果回传和数据库写入是否成功？

遵守客户内网的授权与安全策略，不绕过认证或审计。

## 证据表（现场复用）

| 层级 | 已观察事实 | 当前假设 | 不破坏环境的检查 | 结论 |
|---|---|---|---|---|
| DNS | 待填写 | 记录有误 | 查询 DNS | 未证实 |
| 网络 | 待填写 | 端口不可达 | 连接测试 | 未证实 |
| 代理 | 待填写 | 上游指向错误 | 配置/日志只读检查 | 未证实 |
| 容器 | 待填写 | 映射不一致 | docker ps/inspect | 未证实 |
| 应用 | 待填写 | 服务未就绪 | 日志/健康检查 | 未证实 |
| 依赖 | 待填写 | API/数据库异常 | 只读指标/日志 | 未证实 |

任何排障结束时，说明“我们已经排除了什么、尚未排除什么、下一个最有信息量的动作是什么”。
